# Ownergebundener Datei-Commit: isolierter v2-Versuch

`experiments/studio-device-http/owned-fixture-file-commit.mjs` ist ausschließlich eine synthetische Fixture für markierte Verzeichnisse direkt unter `/dev/shm`. Sie wird von keiner produktiven Route importiert. Ein Uploadticket wird zweimal unter demselben SQLite-Writerlock geprüft: gebundenes Gerät, Upload-Capability, Ticketablauf, aktives Grant und zugehöriges Projekt mit exakt gleichem Owner, Workspace und Projekt-Epoche. Die Verknüpfung der kleinen Testdatei und das Anlegen ihres Receipts geschehen innerhalb dieser Sperre. Das Receipt speichert die Projektbindung. Ein gleichzeitig eintreffender Geräte- oder Projektwiderruf wird damit vor oder nach der Veröffentlichung serialisiert; nach erfolgtem Widerruf ist auch die Receipt-Abfrage gesperrt.

Fünf neue synthetische Tests decken fehlende oder falsche Berechtigung, Projekt-Neuanlage, Ablaufen oder Widerruf nach dem Dateilink, Widerruf über zwei echte Prozesse, manipulierte Bytes, Tombstones und Prozessabbruch nach dem Link ab. Ein unbekannter Dateirest wird nicht automatisch übernommen oder gelöscht. Die vier Reentranzvarianten im Uhr-Callback dienen nur adversarialen Tests; der vorgesehene Vertrag verlangt eine kurze, reine Zeitquelle ohne Seiteneffekte. Daneben liefen 13 bestehende Tests des ownergebundenen Authkerns. Insgesamt 18/18 bestanden.

Dies ist kein fertiger Uploadpfad: Es fehlen die echten Account-/Workspace-/Projektadapter und explizite UI-Freigabe, Android-v2-Enrollment/HTTPS, produktive Datei-/Löschintegration, Speicherung/Rotation der Server- und Geräteschlüssel, Restore-/Migrationskonzept, Quoten/Retention, reale End-to-End- und Ausfalltests sowie unabhängiger Review. Kein Benutzer- oder Serverzustand wurde verändert. SIGKILL simuliert keinen Stromausfall und `/dev/shm` beweist keine Dateisystem-Dauerhaftigkeit. Ein Browser-Logout widerruft hier nicht automatisch ein bereits separat freigegebenes Geräteticket; diese Produktentscheidung muss für eine echte Integration ausdrücklich festgelegt werden. Die bestehende Beschränkung, ein widerrufenes Projekt-Grant nicht erneut freizugeben, bleibt bestehen.
